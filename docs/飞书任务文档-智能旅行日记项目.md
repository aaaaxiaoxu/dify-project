# 智能旅行日记项目任务文档（飞书版）

更新时间：2026-03-25

## 1. 文档目的

本任务文档用于统一当前项目的迭代目标、任务范围、问题清单、优先级、验收标准和建议排期，方便直接同步到飞书文档、飞书任务或周会材料中使用。

本轮迭代的核心目标不是继续“堆功能”，而是先把项目从“可演示”提升到“核心流程可用、关键风险可控”的状态。

---

## 2. 项目背景

### 2.1 项目定位

“智能旅行日记”是一个面向个人旅行记录场景的应用，支持用户注册登录、日记记录、地图足迹、图片/视频展示、AI 文本分析、分享访问等功能。

### 2.2 当前技术结构

- 前端：`uni-app`
- 前端目录：`diary2/`
- 后端：`Flask + SQLAlchemy + JWT`
- 后端目录：`backend2/`
- AI 能力：本地文本分析 + Dify 调用
- 数据类型：用户、日记、图片、视频、AI 分析、分享链接、地图轨迹

### 2.3 当前阶段判断

从现有代码和页面结构看，项目已经具备基础原型，但还存在较多“页面有了、接口有了、闭环没打通”或“能跑通但不适合上线”的问题，尤其集中在以下几个方面：

- 注册流程不完整，存在直接失败风险。
- 密码与配置存在明显安全问题。
- 上传链路、分享链路、媒体链路没有真正闭环。
- 首页、地图页、个人中心的统计逻辑部分为模拟值或错误值。
- 部分功能只有展示入口，没有对应后端能力或真实页面。

## 3. 本轮迭代目标

### 3.1 总体目标

本轮迭代聚焦 4 件事：

1. 修复阻塞核心流程的高优先级 Bug。
2. 补齐“注册-登录-写日记-上传媒体-查看详情-分享”的最小可用闭环。
3. 修正统计、地图、个人中心等关键展示数据，避免演示与实际逻辑不一致。
4. 为后续增强能力（草稿、富文本、AI 结果复用、后台管理）留出清晰的扩展接口。

### 3.2 本轮交付标准

若本轮完成，项目应达到以下状态：

- 新用户可正常注册、登录，并成功进入系统。
- 用户可创建、编辑、删除日记，并正确保存图片、视频、时间、地点、情绪和正文。
- 上传文件后可稳定访问媒体资源。
- 分享链接可在真实环境中打开，不因服务重启立即失效。
- 首页、个人中心、地图页展示的统计数据与真实业务一致。
- 关键安全问题完成最低限度治理，避免明文密码、硬编码敏感配置直接暴露。

## 6. 当前关键问题清单

以下问题建议作为本轮优先修复项。

### P0：立即处理

1. 注册接口未写入 `nickname`
   - 风险：`nickname` 在模型中为非空字段，注册请求缺少该字段时可能直接写库失败。
   - 影响：新用户无法顺利注册，属于核心流程阻塞。

2. 密码明文存储与明文校验
   - 风险：用户信息泄露风险高，不满足基本安全要求。
   - 影响：不适合上线演示或对外试用。

3. 媒体保存直接使用本地临时路径
   - 风险：前端选图/选视频后如果未先上传，后端保存的是不可复用的临时文件路径。
   - 影响：换设备、刷新、重启后图片/视频可能失效。

4. 上传接口返回的资源地址不可保证可访问
   - 风险：即使文件写入成功，前端仍可能无法访问资源。
   - 影响：媒体展示链路不稳定，直接影响核心体验。

5. 分享链接使用 `localhost` 或服务端内存存储
   - 风险：真实用户无法打开；服务重启后全部失效。
   - 影响：分享功能只具备演示价值，不具备实际可用性。

6. 默认密钥和硬编码数据库配置暴露
   - 风险：敏感信息泄露、安全边界缺失、环境切换困难。
   - 影响：部署风险高，维护成本高。

### P1：本轮补齐

1. 个人资料编辑缺失
2. 首页/个人中心统计口径错误
3. 地图里程和天数为模拟值
4. AI 分析结果没有落库和历史读取能力
5. 缺少公开分享页，分享后只能拿到 JSON

### P2：后续增强

1. 草稿保存/自动恢复
2. 富文本编辑器升级
3. 腾讯云 COS 接入
4. AI 图片识别/图片描述
5. 后台管理与审计能力

## 7. 任务拆解

以下内容适合直接拆成飞书任务。

### 任务 1：修复注册流程闭环

- 优先级：P0
- 负责人建议：后端主责，前端配合
- 预计工作量：0.5 到 1 人天

#### 目标

保证新用户可以稳定完成注册，并在字段校验失败时获得明确提示。

#### 现状

- 注册接口目前只接收 `username`、`phone`、`password`
- 用户模型中 `nickname` 为必填字段
- 注册时只校验用户名唯一性，没有校验手机号唯一性、必填项完整性、格式合法性

#### 交付内容

- 后端注册接口补充 `nickname`
- 增加手机号唯一性校验
- 增加请求参数完整性校验
- 返回统一错误信息
- 前端注册页面与接口字段保持一致

#### 验收标准

- 使用新手机号、新用户名注册可成功
- 使用重复用户名时明确报错
- 使用重复手机号时明确报错
- 缺少昵称、手机号、密码等必填项时不写库，并返回可读错误提示

#### 涉及目录

- `backend2/routes/user.py`
- `backend2/models.py`
- `diary2/pages/register/register.vue`

### 任务 2：完成密码安全与配置治理第一轮

- 优先级：P0
- 负责人建议：后端主责
- 预计工作量：1 人天

#### 目标

把项目从“开发演示阶段的裸配置”调整到“可部署、可交付的基础安全状态”。

#### 现状

- 密码为明文存储与明文查询
- `SECRET_KEY`、`JWT_SECRET_KEY` 使用默认值
- 数据库连接直接写在配置文件中

#### 交付内容

- 密码改为哈希存储
- 登录逻辑改为哈希校验
- 敏感配置改为环境变量读取
- 区分开发、测试、生产环境配置
- 补充配置说明文档

#### 验收标准

- 数据库中不再存储明文密码
- 未配置环境变量时，生产环境不允许启动
- 登录仍可正常返回 token
- 部署时不需要修改代码即可切换数据库和密钥

#### 涉及目录

- `backend2/routes/user.py`
- `backend2/config.py`
- `backend2/app.py`

### 任务 3：打通图片/视频上传闭环

- 优先级：P0
- 负责人建议：前后端协作
- 预计工作量：1 到 1.5 人天

#### 目标

确保用户选择图片或视频后，系统先上传文件，再把可访问的正式 URL 写入日记数据。

#### 现状

- 前端目前把本地临时文件路径直接放进 `images` 或 `videos`
- 后端虽然有 `/file/upload`，但前端没有完整接入
- 上传目录与静态资源访问没有完整闭环

#### 交付内容

- 前端新增“选择文件 -> 上传 -> 获取 URL -> 保存日记”的完整流程
- 后端补充文件类型、文件大小、文件名冲突处理
- 配置静态资源访问路径
- 上传失败时前端给出明确提示，不允许写入无效媒体地址

#### 验收标准

- 新建日记上传图片后，列表页和详情页可正常显示
- 新建日记上传视频后，详情页可正常播放
- 服务重启后已上传媒体仍然可访问
- 非法文件、超大文件上传时可正确拦截

#### 涉及目录

- `backend2/routes/file.py`
- `backend2/app.py`
- `backend2/config.py`
- `diary2/pages/diary/edit.vue`

## 10. 风险与依赖

### 10.1 主要风险

- 当前后端部分逻辑仍带有“示例实现”特征，联调时可能暴露更多隐藏问题。
- 上传、分享、地图、AI 统计是跨页面联动模块，改动后需要完整回归。
- 如果本轮同时接入 COS、富文本、后台管理，迭代目标会被摊薄。

### 10.2 依赖项

- 需要明确真实部署域名或公网地址，用于分享链接和媒体访问地址生成。
- 需要确认数据库表结构是否允许新增分享表、分析结果字段和用户资料字段。
- 需要约定前后端统一的返回格式和错误码口径。
